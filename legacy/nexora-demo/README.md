# NEXORA Trading — демо-frontend платформы и CRM

Интерактивный интерфейс торговой платформы (крипта, акции, индексы, форекс, сырьё/металлы), кабинета клиента,
CRM и админки. **Всё на тестовых данных**: реальных сделок, платежей и серверной авторизации нет.

## Запуск

**Основной способ — сайт в браузере по HTTP/HTTPS.**

```bash
python tools/serve.py
```

Откройте http://localhost:8080/ (платформа) и http://localhost:8080/crm.html (CRM). Нужен только Python 3.
Подойдёт любой статический хостинг (Nginx, GitHub Pages, Netlify) — сборка не требуется.

**Автономный файл:** `dist/nexora-standalone.html` — всё (CSS, JS, иконки) внутри одного файла.
Пересобрать: `python tools/build.py` (создаёт также `dist/nexora-trading-source.zip`).

> На телефоне встроенные просмотрщики скачанных HTML-файлов (Файлы, Telegram, почта) часто **не выполняют JavaScript** —
> страница будет пустой. Откройте файл в браузере (Chrome/Safari) или по ссылке http(s)://.

## Живые цены: основной и запасные API (необязательно)

Запуск через `python tools/serve.py` включает шлюз котировок (`tools/providers.py`). У каждого раздела — основной API и запасные:

| Раздел | Основной | Запасные | Ключ |
|---|---|---|---|
| Криптовалюты (50) | Binance (текущая цена и свечи) | CoinGecko (ключ Demo: изменения 7д/30д/1г и монеты вне Binance, раз в 5 мин ≈ 8 600 запросов/мес) → OKX | `COINGECKO_API_KEY` (необязательно) |
| Акции (49) | Yahoo Finance* (до подключения Alpaca) | Twelve Data | `TWELVEDATA_API_KEY` |
| Форекс (63) | Twelve Data: открытая пара получает дневной бюджет (равномерно до сброса в 00:00 UTC, ≈ раз в 2 мин, не чаще 15 с); остальные — по очереди раз в 3 ч, между обновлениями из кэша / Yahoo | Yahoo Finance* → Frankfurter (ECB) | `TWELVEDATA_API_KEY` |
| Металлы | Yahoo Finance* (фьючерсы) | Twelve Data (только золото на бесплатном тарифе) | — |
| Индексы (18) | Yahoo Finance* | — (симуляция) | не нужен |
| Энергоносители и агросырьё | История — Yahoo Finance* (фьючерсы); **текущая цена — симулятор для демо-сделок**, привязанный к последней реальной котировке (плавная перепривязка за 10 мин), с пометкой «СИМ · демо-цена» | — (симуляция) | не нужен |
| Стакан (криптовалюты) | Binance, 8 уровней на сторону, обновление каждые 2 с | OKX | не нужен |

**Стакан** показывается в терминале под формой ордера (только для криптовалют). Клик по уровню лишь подставляет цену в лимитный ордер; демо-ордера на биржу не отправляются. Без шлюза (автономный файл) стакан берётся напрямую с Binance.

\* Yahoo Finance — неофициальный источник без лицензии на коммерческий показ; только для этапа тестирования.

**Кредиты Twelve Data (бесплатно: 8 в минуту и 800 в день на ключ)** отданы форексу. Шлюз ведёт дневной счётчик (`tools/.twelvedata_usage.json`, в архив не попадает); когда дневной лимит исчерпан, форекс до 00:00 UTC идёт с Yahoo. Один ключ, используемый в нескольких местах, делит оба лимита.

**Как работает переключение.** Основной API отдаёт то, что успевает в рамках своих лимитов (приоритет — открытый инструмент, позиции, избранное),
остальное запрашивается у следующего API. Ошибка или таймаут → запрос уходит к запасному. После 3 ошибок подряд провайдер ставится на паузу на 2 минуты.
Если не ответил никто — используется симуляция (пометка «СИМУЛЯЦИЯ»). В интерфейсе видно, какой API отдал цену, и пометка «запасной API», если это был резерв.

**Аналитика.** «Администрирование → Источники данных»: для каждого раздела порядок API (↑/↓ — выбрать основной), включение/выключение (имитация сбоя),
доступность %, средний отклик и p95, число ошибок, последняя ошибка; кнопка «Проверить все API сейчас» — живой замер скорости каждого провайдера.
Порядок сохраняется в `tools/providers.json`.

**Ключи** — в `tools/.env` (образец `tools/.env.example`). В браузер, ZIP и автономный файл они не попадают.
Без шлюза (автономный файл, статический хостинг) живая только крипта: CoinGecko → Binance напрямую из браузера.

Сделки, счета и платежи остаются демо даже при живых ценах. Для показа цен реальным клиентам нужны коммерческие тарифы и лицензии на данные.

## Демо-доступ

На экране входа — кнопки «Клиент / Менеджер / Администратор». Роль можно сменить в верхней панели или меню аккаунта.
Роль хранится отдельно в каждой вкладке: откройте кабинет и CRM в двух вкладках — изменения видны в обеих.
Сброс данных — кнопка «Сбросить демо-данные» вверху.

## Структура

```
index.html, crm.html      точки входа (платформа / CRM), общий код
css/app.css               стили (палитра и элементы исходного дизайна)
js/core/                  утилиты, i18n (RU/UK/EN), состояние и шина событий
js/data/catalog.js        каталог инструментов (опорные цены — из исходного демо)
js/data/market.js         единый источник цен: симулятор + наложение живых данных
js/data/live.js           живые цены во фронтенде (опрос шлюза, режим без шлюза)
tools/providers.py        шлюз котировок: адаптеры API, основной/запасные, кэш, лимиты, метрики
js/data/ledger.js         правила учёта: баланс, позиции, комиссии, P&L
js/data/demo-server.js    эмулятор backend: хранение, бизнес-правила, права (удаляется при подключении API)
js/data/api.js            слой доступа к данным — единственная точка, которую видят компоненты
js/ui/                    компоненты, график (canvas), индикаторы
js/views/                 экраны: auth, terminal, heatmap, analysis, cabinet, crm, admin
docs/API_CONTRACTS.md     контракты API для backend; docs/types.d.ts — типы данных
legacy/                   исходный файл демо без изменений
```

## Ограничения

- Без ключей и сервера живые только цены крипты (CoinGecko); остальное — симуляция от опорных цен исходного демо.
- Данные хранятся только в этом браузере (localStorage), синхронизации между устройствами нет.
- Ограничения доступа в интерфейсе — подсказки; настоящие права должен проверять сервер.
- Пароли, документы KYC и полные адреса кошельков не сохраняются.

## Что нужно от backend

Аутентификация и сессии, проверка прав на каждый запрос, поставщик котировок (REST + WebSocket),
исполнение ордеров/учёт счетов, кастодиан/платёжный провайдер для пополнений и выводов, KYC-провайдер,
хранение CRM-данных, уведомления (e-mail/push). Подробно — `docs/API_CONTRACTS.md`.
