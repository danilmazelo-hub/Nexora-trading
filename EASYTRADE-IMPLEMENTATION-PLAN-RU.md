# EasyTrade — подробный план реализации

Редакция: 16.10.2026. План для начинающего разработчика, который выполняет задачи с ИИ-агентом. Это проектный пакет; код приложения в рамках подготовки плана не создавался, команды будущего приложения не запускались. Все 60 задач имеют статус «не начато».

## Как пользоваться

1. Начни с [START-HERE-RU.md](START-HERE-RU.md).
2. Отмечай собственный прогресс в [DEVELOPER-ROADMAP-RU.md](DEVELOPER-ROADMAP-RU.md).
3. Давай агенту одну задачу по её ID, используя [шаблон задания](TASK-PROMPT-TEMPLATE-RU.md).
4. Сначала агент выполняет части БД → backend → frontend, затем проверки. Если слой уже готов и не меняется, агент объясняет, как переиспользовал его; не создаёт пустые миграции ради чек-листа.
5. Прочитай отчёт, запусти проверки и выполни ручное действие из карты. Только после этого переходи к следующему ID. Ошибку исправляй в текущей задаче.
6. На контрольной точке G1–G9 проверь весь законченный сценарий. Наличие экрана или зелёный build не означает готовности его действий.

## Два этапа и граница между ними

**Этап 1 — полная демоверсия.** Собственная реализация интерфейса и сценариев под брендом EasyTrade, виртуальные средства, воспроизводимые котировки, серверное хранение и все разделы. Скрытые/непроверенные механики оригинала проектируются явно, а не выдаются за точную копию. Не переносить найденные баги и инвестиционные обещания.

**Этап 2 — реальные интеграции.** Выбор продуктов/провайдеров, market data, брокерское исполнение, PSP/custody, KYC, биллинг, безопасность и эксплуатация. Начинается после приёмки D44. Sandbox испытания входят в этот этап; реальные средства допускаются лишь в R15 после предшествующих проверок.

Контрольные точки, рабочие пакеты и номера задач — подразделы этих двух этапов, а не дополнительные этапы проекта. Оценка в днях заранее не фиксируется: новичок движется по подтверждённому результату.

##

Ранний план предлагал преимущественно frontend и IndexedDB. Здесь выбран один backend и PostgreSQL уже для демо, чтобы последовательно учиться строить данные, контракты и UI и не переносить учёт из браузера позднее. Это увеличивает стартовую настройку, но позволяет проверять реальные транзакции БД, изоляцию сессий и идемпотентность с первого этапа. Ранний документ сохранён как [источник](REFERENCE-PLAN-2026-10-14-RU.md), он не является активным списком задач.

Начальный стек: TypeScript; frontend React + Vite + React Router + TanStack Query; backend NestJS как модульный монолит; PostgreSQL + Prisma; общие схемы контрактов и decimal-арифметика. Один репозиторий, один backend, одна БД. Монорепозиторий не означает микросервисы. В D01 агент проверяет совместимые версии и официальные инструкции, фиксирует их и lockfile. Точный API библиотек не берётся из памяти или старых примеров.

Модель структуры и правила: [гайд агента](AI-AGENT-PROJECT-STRUCTURE-GUIDE-RU.md). Предлагаемая структура и сущности EasyTrade: [ARCHITECTURE-AND-DATA-RU.md](ARCHITECTURE-AND-DATA-RU.md). Имена apps/web и apps/api в нашем проекте соответствуют frontend и backend в универсальном гайде.

## Что обязательно для демо, а что можно подключить дополнительно

Демо самостоятельно работает без внешних API, ключей, платёжных SDK, действующих кошельков и настоящих ID-документов. Все сценарные данные помечены Demo; security-переключатели не изображают реально включённую MFA.

Живые справочные цены — необязательное расширение адаптера D10 после готового симулятора. Кандидаты: CoinGecko для справочника крипто, Binance для market data, Alpaca для американских акций, Twelve Data для Forex, Massive для EOD-индексов, EIA для энергетической истории. Бесплатный ключ не гарантирует права публичного показа, live-доступ и полный каталог. До включения проверить актуальные условия/символы/лимиты и кешировать на сервере. EOD, delayed и live не смешивать; справочный feed не является исполнением сделки. Демо с живой справочной ценой всё равно не превращается в реальный счёт.

## Общий критерий завершения задачи

Есть нужная миграция либо обоснованное переиспользование схемы; серверный контракт и отрицательные сценарии; подключённый UI; корректные состояния и подписи; пройдены применимые проверки; данные сохраняются; соблюдены права владельца. Зафиксированы изменённые файлы, команды, их реальные результаты, commit и ограничения. Если проверка не запускалась, статус «не проверено», а не Passed.

Следующая задача выполняется только после приёмки предыдущей. Если выявлен дефект её зависимости, вернись к ней и запиши исправление. Новичку не нужно поручать агенту несколько зависимых карточек одновременно.
