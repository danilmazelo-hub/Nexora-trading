# 0003. Канал обновлений котировок: Server-Sent Events

Дата: 2026-10-16. Статус: принято (D11).

## Контекст
Экраны должны получать обновления котировок, переживать разрыв соединения без дублей и не размножать соединения.
Поток однонаправленный (сервер → браузер); команды идут обычными HTTP-запросами.

## Решение
- Один SSE-endpoint `GET /market/stream?ids=a,b` (через proxy `/api/market/stream`). Одна `EventSource` на вкладку —
  `QuoteStreamManager` в web (`apps/web/src/modules/market-data/quote-stream.ts`) с подсчётом подписчиков по инструментам.
- Событие `quotes`: `{ seq, kind: 'snapshot'|'update', quotes: Quote[] }`, `id = seq` = номер 2-секундного тика рыночного
  времени. Первое событие соединения — всегда полный snapshot (в том числе после reconnect с `Last-Event-ID`).
- Клиент отбрасывает события с `seq` меньше уже применённого; сервер не отправляет повтор того же тика.
- Изменение набора инструментов → одно переподключение с debounce 250 мс; ошибка → закрыть соединение и переподключиться
  с задержкой 1 → 2 → 5 → 10 с (автоповтор браузера отключён, чтобы не было параллельных соединений).
- Данные пишутся в общий кеш TanStack Query `['quote', id]`; страницы не хранят копии цены.

## Почему не WebSocket
SSE работает поверх обычного HTTP через dev-proxy, имеет встроенный `Last-Event-ID`, не требует отдельного протокола
и библиотек; двусторонний канал на этапе 1 не нужен. При необходимости (торговые команды в реальном времени) можно
перейти на WebSocket, сохранив формат событий.

## Последствия
Тикер на сервере работает только при наличии подписчиков (rxjs `share`). Счётчик активных соединений — `GET /market/status`.
