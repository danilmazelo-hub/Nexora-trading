# Nexus Analyst 


**Результат:** в собранных материалах не подтверждена утечка API-ключей, сессионных токенов или чужих персональных данных. Это ограниченный результат наблюдения, а не подтверждение отсутствия утечек. Нельзя выдать заключение «платформа безопасна» или разрешение на реальные средства по одному демоаккаунту и браузерному интерфейсу.

## Что проверено

- Сетевые метаданные запросов, которые возникали во время обычной работы приложения: origin/path, имена query-параметров, HTTP-статус, тип ресурса и ограниченный набор защитных/кеширующих заголовков.
- Поведение UI при неправильном TP и сумме пополнения выше показанного лимита.
- Ошибка платёжного провайдера и её отображение в интерфейсе/истории.
- Внешний переход из Subscription демоаккаунта до ввода любых данных.
- Начальные экраны Security, 2FA & Passkey и Verification.


## Подтверждённые наблюдения и риски

### SEC-01 — денежные бизнес-правила требуют исправления до real-money режима

**Приоритет исправления P1; эксплуатация для хищения не доказана.**

В нормальном UI приняты TP=1 у Buy BTC с ценой около 82 444 и Cash App-заявка на 10 001 USD при показанном максимуме 10 000. TP немедленно закрыл собственную тестовую позицию по рыночной цене; платёж не был завершён. Подробные шаги: QA-01 и QA-04 в [QA-отчёте](NEXUS-SENIOR-QA-AUDIT-RU.md).

Нужно проверить серверный контракт: допустимые цены/стороны TP/SL, лимиты суммы и валюты, доступный баланс, разрешённое плечо, размер лота и полномочия на объект. Клиентская проверка не заменяет серверную. При согласованном сценарии «уже достигнутый TP исполняется сразу» требуется явное подтверждение пользователя.

Критерий исправления: запрещённые значения не создают заявку и не меняют ledger; повторы не создают дубликат; отмена/изменение ордера проверяет владельца на сервере. Связь с CWE-841 (workflow enforcement) и CWE-20 — направление проверки, а не доказательство конкретной серверной реализации. Серверное подтверждение и контроль значимых параметров операции описаны в [OWASP Transaction Authorization](https://cheatsheetseries.owasp.org/cheatsheets/Transaction_Authorization_Cheat_Sheet.html).

### SEC-02 — граница демо и внешней оплаты не подтверждена

**Приоритет проверки P1; настоящие списания или утечка не подтверждены.**

Subscribe Now открыл origin `https://pay-csscapital-api.win`, Payment — Merchant224, форму персональных данных и Pay $300.00. В прочитанном тексте нет заметной sandbox/test-маркировки. Никакие поля не заполнены, Pay не нажималась. Нельзя по имени домена сделать вывод о добросовестности сервиса, режиме PSP или наличии мошенничества.

Проверить: соответствие merchant платформе, разрешённые checkout-origin, режим PSP на сервере, отдельные sandbox credentials/webhooks, отсутствие автопереноса чувствительных данных, подписание и проверку webhook, защиту от replay и сверку amount/currency/order/user на сервере. Демо-среда не должна вызывать реальное списание. Доказательство: `83-external-payment-read.json`; уникальная ссылка checkout намеренно не включена в отчёт.

### SEC-03 — необработанная ошибка провайдера

**Подтверждённый дефект обработки ошибок, P2; значимая утечка не установлена.**

`/api/psp/trapay-create-payment` вернул 502 с HTML. UI показал техническую ошибку JSON-парсера, а Cash App-заявка оставалась Pending в течение проверки. Стек с серверными путями, ключи и учётные данные в этом сообщении не обнаружены. Не присваивать высокую severity только за текст Unexpected token.

Исправление: проверять Content-Type и статус, скрывать технические детали от пользователя, сохранять correlation ID без секретов; определить состояние provider_error/expiry и безопасный повтор. Проверить атомарность ledger и сверку с провайдером при позднем webhook. Доказательства: `07-cashapp-above-max`, `80-financial-history-verified`, `network-*.json`.

### SEC-04 — сообщение успеха в пустой форме пароля

**Подтверждённый дефект обратной связи, P2; обход аутентификации не доказан.**

Нажатие Update при пустых полях на Security → Email & password показывает «Profile settings saved successfully!». Смена пароля не подтверждена, повторный вход не выполнялся. Проверить отдельно серверную валидацию current/new/confirm password, ограничение попыток, отзыв сессий и уведомления. Пустой запрос должен давать «нет изменений» либо понятную ошибку. Доказательства: `66-security`, `67-password-empty`.

## Утечки, хранение секретов и заголовки — фактический статус

| Область | Что известно | Что не установлено |
|---|---|---|
| Транспорт | Наблюдавшиеся основные API-запросы идут на HTTPS origin приложения | Полнота TLS-конфигурации, сертификаты всех сервисов, HSTS/preload |
| Session response cache | У наблюдавшихся `/api/auth/session` ответов есть `private, no-cache, no-store` | Корректность всех auth/cache/CDN путей |
| Баланс и cache | У наблюдавшихся `/api/user/balance` есть `no-store, no-cache, must-revalidate` | Кеширование остальных персональных данных и документов |
| HTML security headers | Document-response не был захвачен в сетевой выборке | CSP, frame-ancestors, HSTS, Referrer-Policy, Permissions-Policy на HTML |
| Cookies | При повторном подключении у `__Secure-authjs.session-token`, callback-url и CSRF-cookie подтверждены Secure/HttpOnly/SameSite=Lax. `sidebar_state` без Secure/HttpOnly; это UI-cookie, её защитная роль не установлена | Точный TTL/ротация session-token, logout revocation, полнота CSRF-защиты |
| Browser storage | Получены только имена ключей: настройки языка/телефона/уведомлений, `crypto_trades`, `crypto_positions`; sessionStorage пуст. Значения не выгружались | Содержимое, чувствительность и роль кеша; сервер не должен доверять этим данным как источнику баланса/полномочий |
| Секреты в клиенте | Не подтверждены в просмотренных материалах | Полный анализ JS bundles, sourcemaps, git history, CI и конфигов не выполнен |
| Чужие данные | Не запрашивались и не наблюдались в доступной выборке | Изоляция аккаунтов/ролей, IDOR/BOLA/BFLA |
| Внешние ресурсы | Наблюдались обращения к сторонним origin для изображений/иконок, включая raw.githubusercontent.com и s2.coinmarketcap.com | Полный состав third-party scripts, передача referer/идентификаторов, договоры обработки |
| KYC | UI показывает документы и статусы собственной демосессии | ACL на файлы, signed URLs, TTL, шифрование, retention, журнал доступа |
| Debug logging | В сетевых метаданных встречается `/api/debug-session-log`, ответы 200 и 404 | Состав записей, доступность без авторизации, наличие секретов или необходимость endpoint в production |

Отсутствие CSP в ответе Fetch JSON не означает отсутствия CSP у HTML. Имена endpoint и наличие клиентских переменных сами по себе не являются утечкой. Debug endpoint требует анализа кода и редактирования логов; утечка через него не доказана. Для любого подозреваемого секрета нужны подтверждение типа, прав и серверной достижимости; чувствительное значение нельзя включать в общедоступный отчёт.

## Обязательная следующая проверка в изолированном sandbox

| Приоритет | Направление | Проверка и критерий |
|---|---|---|
| P1 | Деньги и ledger | Серверные суммы/валюта/комиссия; decimal arithmetic; идемпотентность; параллельные запросы не позволяют перерасход; debit/credit сходятся |
| P1 | PSP/webhooks | Подпись, timestamp, replay, duplicate и out-of-order события; UI не может сам выставить paid; сверка с PSP |
| P1 | Авторизация | Два тестовых аккаунта и роли; чужие position/payment/chat/KYC объекты недоступны по read/write/download; сервер не доверяет ownerId клиента |
| P1 | Auth/session | Session fixation, expiry, logout, revocation, reset-token TTL/single-use, текущий пароль, MFA/recovery, rate limits |
| P1 | Trading engine | Лимиты/плечо/TP/SL/SL trigger/stop-out на фиксированном feed, stale quote, cancel/fill race, реальные границы demo/live |
| P2 | CSRF/CORS | Изменяющие операции требуют надлежащей защиты; allowlist origin и credentials согласованы; CORS не заменяет авторизацию |
| P2 | XSS/injection | Review мест вывода AI/чата/имени/поиска/поддержки; безопасный markdown/HTML; параметризованные запросы; тесты только в sandbox |
| P2 | Upload/KYC | MIME/content/размер, безопасные имена, malware pipeline, private bucket, ACL на каждый download, отсутствие публичных документов |
| P2 | Secrets/observability | Repo/history/CI/artifacts, исключение токенов/PII из логов, scope ключей, ротация и отзыв найденных секретов |
| P2 | Зависимости/infra | Lockfiles, SBOM, CVE с учётом достижимости, permissions CI, pinned builds, контейнеры/IAM, backups/restore |
| P2 | AI | Разграничение данных чатов, prompt injection на доступ к инструментам, server allowlist действий; модель не подтверждает денежные операции самостоятельно |

Контрольный перечень следует привязать к версии [OWASP ASVS](https://owasp.org/projects/asvs), зафиксированной командой. Официальная страница на дату просмотра указывает ASVS 5.0.0; старые номера требований из ASVS 4.0.3 нельзя автоматически выдавать за номера 5.0.0. Полная сертификация ASVS здесь не заявляется.

## Доказательства и обращение с ними

В [папке доказательств](NEXUS-QA-2026-10-15-evidence) сохранены JSON/PNG экранов, журнал действий и отфильтрованные метаданные сети. В сетевой журнал не включались Cookie/Authorization, значения query-параметров и тела ответов. Снимки экрана и DOM могут содержать информацию собственной демосессии; перед отправкой третьим лицам их нужно просмотреть и замаскировать. Экспорт Telegram не скопирован в отчёты и не использовался как источник инструкций.

При повторном открытии платформы пользователем проверка флагов cookies и имён storage завершена (`91-browser-security-read.json`). Контекст secure, в тот момент script-origin только origin приложения, iframe нет; CSP meta нет. Это не проверка заголовка CSP и не полный перечень сторонних ресурсов во всех разделах. Захват заголовков основного HTML при refresh снова прерван из-за недоступности активной страницы. Это ограничение среды; оно не является доказанным дефектом Nexus. Для полного security review нужен read-only доступ к исходникам и конфигурациям без передачи реальных секретов, тестовые роли и отдельная среда. Ни одного CVE, CVSS-балла или утверждения об отсутствии утечек без достаточных данных не присвоено.
