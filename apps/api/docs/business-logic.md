# Бизнес-логика: журнал денег и симулятор цен

## Журнал (modules/ledger, domain/ledger-rules.ts)
- Use case `LedgerService.post(command)`: `{ scope, idempotencyKey, type, memo?, entries: [{ ledgerAccountId, asset, amount }] }`.
- Шаги: проверить проводки (`validateEntries`: ≥ 2 проводки, ненулевые суммы, сумма 0 по каждому активу) →
  вычислить `requestHash` (sha-256 канонического JSON команды) → в одной транзакции: найти транзакцию по
  (`scope`,`idempotencyKey`); если есть и хеш совпадает — вернуть её (`replayed: true`); если хеш иной — 409
  `IDEMPOTENCY_CONFLICT`; иначе создать транзакцию и проводки. Гонка двух одинаковых команд разрешается unique-индексом:
  проигравший получает P2002 и перечитывает существующую.
- Остаток `getBalances(accountId)` = `SUM(amount)` по `LedgerAccount` счёта, сгруппировано по активу.
- Исправление — `reverse(transactionId)`: новая транзакция с противоположными суммами и `reversalOfId`.

## Симулятор (domain/market-sim)
Перенос детерминированной модели из прежнего демо: дневные закрытия (лог-случайное блуждание с возвратом к опорной
цене) → 5-минутный броуновский мост → тики по 2 с. Всё — функция `(seed, instrument, time)`; одинаковые входы дают
одинаковые цены. Свечи старших интервалов — агрегаты 5-минутных, поэтому все представления согласованы.
Изменение цены — в процентных пунктах относительно цены 24 ч назад (crypto) или закрытия предыдущего UTC-дня (прочие),
период указывается в ответе (`changePeriod`).
